    ACTION BOUNDARY

    The valuable part is the authority design.

    Model capability changes every month. This contract remains stable: what the job can read, what it can change, and what must stop for a person.

    May do

    • Read public pages and repository files
    • Run deterministic checks
    • Deduplicate and update queue state
    • Prepare an isolated source repair

    Ask first

    • Change public copy or prices
    • Merge or deploy a repair
    • Change a Google Calendar setting
    • Relax an acceptance rule

    Never do

    • Publish on its own authority
    • Invent results or client claims
    • Treat HTTP 200 as business success
    • Hide an unresolved exception
    THE LOOP

    Each run advances the same queue.

    1. Observe

    Read the live journey, source, and external handoff.

    2. Reconcile

    Compare evidence with the approved product contract.

    3. Decide

    Classify code repair, external owner action, or no work.

    4. Act or hold

    Prepare bounded work and stop at the approval line.

    5. Verify

    Rerun after the change and close only with evidence.
